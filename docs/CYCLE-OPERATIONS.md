# ALPHA Builders cycle operations

These controls make each pilot cycle auditable without adding a private analytics stack.

## Cycle ID

Every new submission generated by the site includes a public `Cycle ID` such as `alpha-abcdef123456`.

Use the same identifier in:

- the pilot start Issue;
- the submission Issue;
- the feedback Issue.

This connects start, delivery and feedback while keeping the source of truth in GitHub.

## Wallet proof expiry

The signed wallet message includes `Proof Created At`.

Automated validation accepts the proof only when it is no more than 15 minutes old. If the proof expires, the participant should generate a fresh submission from the site.

## Pull Request authorship

For Pull Request evidence, the workflow checks that:

- the PR targets the submitted repository;
- the PR changes a README file;
- the Issue author is the PR author or authored at least one PR commit.

Submissions that fail authorship validation move to `needs-review`.

## Private feedback

The public feedback form records whether the participant prefers public or private follow-up.

Private feedback content must not be posted in GitHub Issues. The public metric counts the request only.

## Operations dashboard

`/operations` exposes:

- started cohort entries;
- open review queue;
- review age in hours;
- SLA breach status using the 48-hour target;
- rubric version used for accepted reviews.
